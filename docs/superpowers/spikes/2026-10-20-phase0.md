# Phase 0 spikes (2026-10-20)

Probe script: `spikes/s1_decide_probe.py` (throwaway). Run date: 2026-10-20. All responses below are verbatim from live calls; the `Authorization` header is never recorded and one `user_id` field in an error body is redacted.

## S1: Mercury Decide API

**Verdict:** GO. The endpoint exists, works on both models, accepts images, and the free tier did not rate-limit a 40-way burst. Two shape differences from the research (below): the boolean type is `noul`, and responses carry `legend`/`confidence` extras.

### Endpoint

`POST https://openrouter.ai/api/v1/systemone`

- Headers: `Authorization: Bearer <OPENROUTER_API_KEY>`, `Content-Type: application/json`.
- 404 fallbacks (`/decisions`, `/evaluate`) were not needed.
- Models: `inception/mercury-decide:free` and `inception/mercury-decide` (paid). Both resolve to `"model": "inception/mercury-decide-20260930"` in responses.
- `GET https://openrouter.ai/api/v1/models` does NOT list decision models by default. Use `?output_modalities=all` (or `decisions`). Valid `output_modalities` values per the API: `text, image, embeddings, audio, video, rerank, decisions, speech, transcription, all`.
- Verbatim model-list facts, identical for both ids: `architecture.modality` = `"text+image->decisions"`, `architecture.input_modalities` = `["text","image"]`, `architecture.output_modalities` = `["decisions"]`, `supported_parameters` = `[]`, `context_length` = 65536, `top_provider.max_completion_tokens` = 58982. Pricing: paid `{"prompt":"0.00000002","completion":"0","input_cache_read":"0"}`; free `{"prompt":"0","completion":"0"}`.
- Same API contract is shared by other decision models on OpenRouter (`upstage/solar-decide`, `perplexity/pplx-decider-v1.2`, ...).

### Request (boolean / choice / score)

One request carrying all three question types (this exact body succeeded, HTTP 200):

```json
{
  "model": "inception/mercury-decide:free",
  "state": {
    "ticket": "I was charged twice for my subscription this month and the app keeps crashing."
  },
  "questions": {
    "is_billing_issue": {
      "type": "noul",
      "instructions": "Does the ticket concern a billing problem?"
    },
    "category": {
      "type": "choice",
      "instructions": "Which category best fits the ticket?",
      "criteria": {
        "billing": "Charges, refunds, invoices",
        "bug": "Software crashes or malfunctions",
        "other": "Anything else"
      }
    },
    "urgency": {
      "type": "score",
      "instructions": "How urgent is the ticket?",
      "criteria": ["not urgent", "somewhat urgent", "urgent", "critical"]
    }
  }
}
```

- Boolean: `"type": "noul"` (NOT `"boolean"`; see Field-name variants). `criteria` omitted.
- Choice: `criteria` is an object `{option: description}`.
- Score: `criteria` is an ordered list, lowest rung first (index = score value).
- `state` accepted as an object (above) and as a message-style array (see Images). A plain string was not tested.

### Implications for the client

- POST to `https://openrouter.ai/api/v1/systemone` with `{"model", "state", "questions"}`. Map the factory's `boolean` type to the wire type `"noul"`; keep `choice` (criteria = dict) and `score` (criteria = ordered list, lowest rung first).
- Parse by answer `type`: `noul` -> `answer["noul"]` (P(true)); `choice` -> `answer["choice"]` plus `probabilities` and `confidence`; `score` -> float `answer["score"]` (round or threshold it yourself) plus `legend`, `probabilities`, `confidence`. Ignore unknown extra fields.
- Images need no special handling: pass `state` as a message array with `image_url` data-URL parts. Task 15 should take branch B (images accepted). Keep it to `data:` PNG/base64 unless remote URLs are verified.
- Timeout and fallback (binding constraints): use a 5 s timeout per Decide call. On HTTP 429, any 5xx, a timeout, or a connect error, fall through IMMEDIATELY to the next model in the chain `["inception/mercury-decide:free", "inception/mercury-decide"]`, with no same-model backoff or retry loops. 400 and 401 are neither retried nor fallen through (they are caller or config errors; surface them). The observed worst case, about 1.6 s p95 under a 40-way burst (max single call 897 ms sequentially), fits well inside the 5 s timeout.
- Errors: non-200 responses observed here are `{"error": {"message", "code"}}`, and for 400 validation errors `message` is a JSON-encoded string, so surface it raw. The client must also tolerate a non-JSON body on 5xx (and treat a failed JSON parse as a fall-through error, not a crash). No 5xx or 429 was observed, so those bodies are unverified.
- Models: default to `inception/mercury-decide:free`, with `inception/mercury-decide` as the second link of the chain (identical answers, about $5e-6 per 3-question call). Record `usage` for cost accounting. Reuse one HTTP client for connection pooling.
- Outputs are deterministic for identical input, so identical decisions can be cached safely. Task 6's `client.py` notes should say `noul`, not `boolean`.

- **pi extensions CAN intercept and block tool calls.** `pi.on("tool_call", handler)` fires before execution; returning `{ block: true, reason?: string, terminate?: boolean }` blocks it (docs: `docs/extensions.md` "tool_call"; `event.input` is mutable too). Minimal working example (`spikes/s2_pi_gate.ts`, run with `-e`):

```ts
import { appendFileSync } from "node:fs";
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
export default function (pi: ExtensionAPI) {
	pi.on("tool_call", async (event) => {
		const log = process.env.GATE_LOG;
		if (log) appendFileSync(log, JSON.stringify({ tool: event.toolName, input: event.input }) + "\n");
		if (event.toolName === "bash" && String((event.input as any).command ?? "").includes("BLOCKME")) {
			return { block: true, reason: "GATE-DENIED: command contains BLOCKME" };
		}
		return undefined;
	});
}
```

### Implications for fast-coder

- Use `claude -p` with the exact flag set above; `pi` is a verified backup only (same task passes, with a working `tool_call` block hook), no need to switch.
- Always pass `--setting-sources local` (global user hooks/CLAUDE.md stay out), `< /dev/null`, and wrap in `timeout` (no `--max-turns`). Pass the OpenRouter env vars only on the child (`env ...`), never export them.
- The tool gate can be a `--settings` PreToolUse hook that exits 2 (stderr text goes back to the model as the tool result); the log hook must append only stdin JSON, never env.
- Do NOT trust `total_cost_usd` for budget enforcement: it is about 40x too high. Measure real spend through OpenRouter (`/api/v1/key` `data.usage` delta, with a few seconds' lag) or apply Mercury 3's real rates to `modelUsage` token counts. Real cost is about $0.003 per trivial 6-7 turn job.
- Keep `ANTHROPIC_API_KEY=` empty and use `ANTHROPIC_AUTH_TOKEN`; keep both `ANTHROPIC_DEFAULT_HAIKU_MODEL` and `CLAUDE_CODE_SUBAGENT_MODEL` pointed at mercury-3 so no background call goes to an Anthropic model id that OpenRouter would reject or bill differently.
- Resume works by reusing the `--session-id` uuid with `--resume <uuid>` (same session id returned, context retained), so rework rounds can resume instead of re-sending context.
- Latency is about 7-10 s per small job (about 2 s TTFT). Claude Code overhead is large in tokens (about 144k input tokens per run, mostly cache reads), so keep prompts short and expect pi to be about 10x leaner in tokens if cost ever matters.
- Scratch repos need their own `git config user.email/name`. Keep the hook log and JSON output out of the work tree (here they were in `.git/info/exclude`; the model noticed the untracked files and left them out of the commit, but do not rely on that).

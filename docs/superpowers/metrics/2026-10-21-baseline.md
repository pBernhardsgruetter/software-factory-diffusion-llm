# Baseline metrics: 11 sample-app jobs (2026-10-21)

Produced by `factory/bin/metrics` from the Claude Code transcripts, `jobs/<id>/`
and git of the sandbox repo (no instrumentation, so any past run can be
measured). Re-run it after every change and compare.

```sh
factory/bin/metrics --root . --out factory/metrics     # report.md + <job>.json
```

**How to read it.** `work s` is wall time without human waits (a wait is the
gap before a human prompt; here it includes my scripted pauses between phases).
`orch s` is the part of `work s` covered by no phase: the orchestrator thinking
and calling tools. Subagent costs are tokens x calibrated prices; the prices
are fitted to Claude Code's own per-session `cost-state`, and the subagent and
orchestrator parts add up to that number within 0.4%. Mercury Decide ran on the
free model; Mercury 3 costs come from `job.json`. Phase seconds of parallel
reviewers add up, so the time-share table over-counts parallel work.

## What the baseline says

1. **The orchestrator is half the Claude bill.** The Opus session that follows
   `SKILL.md` costs $21.19 of $42.34 (50%) and 22% of wall time. Even the
   smallest job costs about $1.05 in orchestration alone.
2. **The fast tier saves almost nothing in dollars.** Fast jobs 004 and 008 cost
   $1.58 and $2.03; heavy job 010 (one round, no fixes) cost $2.18. Mercury 3
   itself is $0.003 to $0.014 per job. The build is 22 to 37 s on Mercury 3 against
   66 to 248 s on the Opus builder, but spec, four reviews and the approver stay
   on the critical path, so the whole job still takes about 235 to 262 s.
3. **Rounds drive cost.** One-round jobs cost $1.58 to $2.18; jobs with three or
   more rounds cost $5.4 to $5.8. In the second parallel run most extra rounds
   were merge conflicts, not defects.
4. **The approver is expensive for a gate.** 17 runs, $4.77 (about the cost of
   the whole review stage), mean 39 s, about 3M cached input tokens per run:
   it re-runs tests, build and lint that the reviewers already ran.
5. **Reviewers differ 2.7x in cost.** Opus security review: $2.92 for 18 runs;
   Sonnet code review: $1.10 for 20 runs.
6. **Mercury Decide is fast and cheap but unsure where it matters:** 0.3 to 1 s per
   call and $0, yet `assumptions` is uncertain in 9 of 11 calls and `visual` in
   4 of 7. Triage was uncertain 4 of 11 times.
7. **Not measured yet:** real human think time (needs interactive sessions),
   reviewer quality (defects found per round, false PASS), and the same feature
   built on both tiers.

## Experiment H1: orchestrator on Sonnet 5.5 (2026-10-21)

Same three backlog items (FAQ, Terms, Changelog), same skill (with the sync
step), same confirmation texts, run as three parallel sessions. Control: the
Opus 5.5 run of the same items (jobs 009 to 011). Only `--model` of the
orchestrator differs; subagents keep their own models.

| | Opus orchestrator | Sonnet orchestrator | change |
|---|---|---|---|
| Claude total (Claude Code's number) | $11.92 | $8.14 | -32% |
| orchestrator share | $5.98 (50%) | $2.59 (32%) | -57% |
| subagents | $5.96 | $5.56 | -7% (noise: same agents) |
| work wall time (sum of 3 jobs) | 1552 s | 1305 s | -16% |
| orchestrator-only seconds | 351 s | 239 s | -32% |
| review rounds (sum) | 6 | 6 | same |
| escalations | 1 | 0 | |
| final tree | 66 tests, build, lint ok | 67 tests, build, lint ok | |

Protocol adherence looked equal (same count of triage, clarify, assumptions,
rereview and escalation calls, all four reviewers every time, same merges). One
slip: job 003 recorded 2 escalation outcomes for 3 escalation decisions, which
loses calibration data. n = 3 jobs per arm and review rounds vary between runs,
so treat the totals as indicative; the orchestrator line is the cleanest signal
because it is the only thing that was changed.

**Verdict:** H1 holds. Moving the orchestrator to Sonnet cut about a third of
the Claude bill and a sixth of the wall time without a visible quality loss.
Make it the default only after a second, larger run (at least 6 jobs per arm,
including one that must escalate) and a check that every outcome record is
written.

Note on prices: the fitted prices are effective prices, not list prices (they
depend on context length); the sums add up to Claude Code's own totals within
2 to 5%, which is what the cost split needs.

## Hypotheses to test next (one change each, then re-measure)

| # | change | expected effect | measure |
|---|---|---|---|
| H1 | **tested, holds (see above)** run the orchestrator on Sonnet | orchestrator $ down by roughly half | cost split, defects missed at the gate |
| H2 | trim `SKILL.md` and what the orchestrator re-reads each turn | fewer cache-read tokens per turn | orchestrator tokens per job |
| H3 | approver reuses the reviewers' test/build/lint results instead of re-running | approver $ and seconds down | approve phase mean |
| H4 | triage trivial static pages as fast | fast-tier share up, rounds unchanged | tier mix, rounds |
| H5 | sync with main before the first review round, not only before the approver | fewer conflict rounds in parallel runs | rounds per job under parallel load |
